tamias-publish — author-side packing: a payload dir + manifest → a .tgz (the registry stores these; the http source fetches them).

include: handling (PL-0007 / P-004): by default pack flattens — each base resolves read-only (installed store entry → its payload dir; a ref already installed → the entry whose source_ref matches; an existing fs path → resolved in place) and [tamias_core::overlay] composes them under the local payload in a scratch dir that is packed instead. Publish never installs anything: an unresolvable base fails naming it. keep_includes ships the raw payload dir for consumers that compose themselves.

Flattening is not transitive: a base contributes whatever payload is stored/installed — a store entry is already composed if it had include: at its own install; an fs-dir base’s own include: is not re-resolved (same rule as install’s store-name path). The packed manifest is unchanged — include: stays as provenance.
