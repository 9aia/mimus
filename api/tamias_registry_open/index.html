tamias-registry-open — the shared registry-source layer.

Resolves a registry value — a registries config name first, then a raw dir/http ref — into a Registry impl, and owns the config-file CRUD behind tamias registry add|remove|get|list and the tamias-serve registry.* ops. Both tamias-cli and tamias-serve consume this so name resolution, limit lookup, and config writes can’t diverge (same role tamias-install plays for the install pipeline).

Returns the config path written. http/cf need an http(s) url; local takes a dir (or anything — the explicit kind wins over url-scheme inference at resolve time). id is the optional stable identifier registry-scoped install refs (<id>:<name>@<version>) match before the map key.
config_target
The config file registry management verbs read/write — file, then TAMIAS_CONFIG, then ./tamias.{yml,yaml,toml} discovery. No file anywhere → ./tamias.yml + defaults (created on write). The returned [Config] is that file’s own — never the merged read view — so writes can’t flatten a lower layer’s entries into the upper file, and a bare registry add in an empty dir still creates a project tamias.yml rather than silently editing the global config (pass --file ~/.config/tamias/tamias.toml for that).

The effective byte limits for a publish/search target — value doubles as the registry name when it matches a registries key (raw dir/http refs simply miss the lookup and get global + package rules). None config → built-in defaults.

publish_plan
publish <dir> [registry] resolution — the shared head of tamias publish, tamias serve’s publish op, and tamias ui’s Author pane: payload_root → Manifest::load → include: flatten (unless keep_includes) → registry_target → open_registry. store_root is the install store the flatten resolves bases against — read-only, publish never installs. report fires after the manifest loads and the target resolves but before the registry opens, so each surface keeps its own “publishing …” line in its own position (the CLI prints post-open; the TUI logs pre-open).
