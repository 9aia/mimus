tamias-tui — the interactive package-manager surface behind tamias ui (ratatui/crossterm, PL-0004). Phases 1–3: the Installed pane lists store entries with a / filter, Enter opens a detail view, and v/u/p/r/c/d/i run the same library calls tamias-serve/the CLI use on worker threads (confirm + consent modals, streamed phase log); the Registry pane searches a registry as-you-type and i installs a result. Services/Manifest/Author stay placeholders until their phases land. Terminal discipline mirrors myco-tui: alternate screen, raw mode, a drop guard, a panic hook, mouse capture, and a notify watcher on the store root that reloads the entry list when installs land from another tamias invocation.

The crate stays engine-free: it reads the store through tamias-store-local directly and takes its roots from Ctx — tamias ui builds one from the CLI env; the standalone tamias-tui bin reads TAMIAS_HOME/TAMIAS_CACHE/TAMIAS_REGISTRY. Later phases call the shared ops (tamias-install, tamias-registry-open, tamias-serve) on worker threads — the Ctx fields are already the serve Env shape so nothing has to be re-plumbed.
