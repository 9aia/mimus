tamias-deploy-launchd — the deploy port’s macOS adapter: manage a per-user launchd agent — a plist under ~/Library/LaunchAgents driven by launchctl. No admin needed: agents load into the caller’s gui/<uid> domain.

A ServiceSpec renders to artifacts under the agent dir ($HOME/Library/LaunchAgents by default):

  • <label>.plist — the agent definition. ProgramArguments takes the exec argv directly (no wrapper needed for argv/env/ workdir): env → EnvironmentVariables, workdir → WorkingDirectory, restart/restart_sec → KeepAlive + ThrottleInterval, RunAtLoad always true (the plist is the “enabled” artifact — install writes it, enable bootstraps it). StandardOutPath/StandardErrorPath point at log files next to the plist — launchd captures stdout/stderr for free, and the logs verb tails them (no journald equivalent needed).
  • <label>.sh — a tiny POSIX-sh wrapper, written only when env_file is set. launchd has no env-file mechanism, so the wrapper sources the file (set -a; . <file>; set +a, guarded by [ -f … ] so a missing file stays non-fatal — systemd’s EnvironmentFile=- semantics) and then exports the inline env entries so inline still wins. ProgramArguments then runs /bin/sh <label>.sh instead of the raw argv. Without env_file no wrapper is generated and env rides the plist dict.
  • <label>.stdout.log / <label>.stderr.log — pre-created empty so tail (and launchd’s own redirection) always have a target.

The label is com.9aia.<name> where <name> is the spec’s unit base name (<provider>-<service>), sanitized to launchd’s conventional charset — see label_for.

§Honest gaps

  • Restart vocabulary is approximate. systemd’s on-failure/always/no map to KeepAlive {"SuccessfulExit": false} / true / absent. SuccessfulExit= false restarts on non-zero exit and on crash/signal, but does not cover every systemd on-failure nuance (e.g. a clean exit during startup). always → KeepAlive=true restarts even after a clean exit(0) — matching systemd always, but note launchd throttles respawns (ThrottleInterval, default 10s). Any other restart value (on-success, on-abnormal, …) degrades to on-failure semantics. restart_sec maps to ThrottleInterval (integer seconds).
  • env_file is sourced by /bin/sh, not parsed by the OS: K=V, export K=V, quoting, and # comments all work (richer than systemd’s parser in some ways), but shell syntax is live — $(…), backticks, and $VAR expand. Treat env files as trusted local data, same as a shell profile.
  • description and after are dropped — plists carry no description field and launchd has no dependency graph.
  • disable persists via launchctl disable (the per-domain override db), enable clears it — closer to systemd’s enable/disable symlink semantics than a bare bootout. Re-running enable on a loaded agent bootouts + bootstraps, i.e. it restarts the service (launchctl has no enable-without-reload).
  • Default working directory. With no workdir, launchd runs the job with cwd / — set workdir in the manifest if the payload expects ~.
  • Real launchctl execution is #[cfg(target_os = "macos")]-gated ([LaunchctlRunner] only exists there); everywhere else LaunchdDeploy::new installs an unavailable runner so verbs fail loudly instead of shelling out. Tests inject a Runner recorder on any platform; arg-builder tests are cfg(unix) (they resolve the gui uid via $UID/id -u).

label_for
The launchd label for a unit base name: com.9aia.<name> with the name sanitized to launchd’s conventional charset ([A-Za-z0-9._-] — @, the only non-conventional char the unit-name grammar allows, becomes -). Sanitization is deterministic but not injective: a@b and a-b collide on com.9aia.a-b — unit names are provider-derived and don’t contain @ in practice.
