Triples → the semantic tier’s candidate list (ADR-0002 ph5).

The buckets own canon-equal subjects (contradiction, self-contradiction); this is the residue they can’t decide. A pair becomes a candidate when all four hold:

  • the canonical subjects differ — canon-equal is the buckets’ job, and re-emitting it would spend an agent call on a mechanical conflict;
  • both triples assert the same relation — different relations are different slots, not a disagreement;
  • the canonical subjects share ≥1 content token — auth pairs with auth flow, never with cache. This is the synonym / near-duplicate heuristic that keeps the intake small;
  • the objects differ — agreeing triples are not a question.

Each unordered pair emits once, and the output is sorted on (relation, left_subject, right_subject, left_object, right_object) so two runs over the same triples print the same prompt. Original spellings survive into the struct: the agent needs the real file:line site, not the bucket key.
