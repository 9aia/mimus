Crate mimus_check_graph 

Source
Expand description

Graph adapter — set-level checking (ADR-0002): index-edge classes against the kuda index (phase 1) plus index-free prose contradiction buckets (phase 2). Consumes the index file format, not the kuda crates — the schema is the contract, same as mimus-check-symbol.

Classes:

  • stale-reference (error): an imports/package-dep/ workspace-member edge whose target resolves to no indexed module — or whose source module is gone entirely. Internal vs external is decided conservatively: an unresolved target flags only when it shares the repo’s own naming family (a ‘/’-scope or a prefix segment carried by ≥2 indexed modules); bare external-looking names (serde, react, github.com/ext/x) are silence.
  • unsupported-claim (warn): prose of the shape X imports|depends on|requires|uses Y where both sides resolve to indexed modules and the index records no such edge. Either side unresolvable → the triple is unproveable → silence (evidence-or-silence, ADR-0001).
  • contradiction / self-contradiction (warn, phase 2): prose claims reduce to (subject, relation, object) triples (mimus-claims::triples) and conflicts fall out of the (subject, relation) bucket — cross-source for doc↔doc, reflexive when one file asserts two objects for the same slot. No index needed: this pass runs on any claim set.
  • phase 3: a per-file triples cache (cache module — sqlite at .mimus/triples.db, keyed on content hash + extractor version) skips re-extracting unchanged files, and the prose pass’s in_scope gate lets --diff keep the buckets whole while only reporting conflicts that touch changed files.
  • phase 5: the semantic tier is rescoped to fuzzy-candidate adjudication. semantic_candidates turns the prose triples the buckets leave unsettled (canon-differing subjects that share a token, same relation, different objects) into the agent’s intake list — pre-filtered, so the agent adjudicates pairs instead of scanning every claim.
  • undocumented-fact (warn, phase 4): reverse coverage — a public module (one the index records as a dependency target) that no claim names is code the docs never assert. Module granularity, not edge: every indexed import is a fact nobody documents, while a module is the smallest unit a doc page can reasonably cover. in_scope gates it the way it gates the buckets — under --diff only modules whose own sources changed report.

Modules§

cache
Per-file triples cache — ADR-0002 phase 3. extract_triples is pure over claims, but claims derive from source files — so the cache sits one level up: per source file, keyed on (path, content hash, TRIPLES_VERSION). Same bytes + same extractor version → sqlite rows instead of re-extraction; an edit changes the hash → the file’s rows are rewritten.

Structs§

IndexEdgeChecker
Set-level graph pass — phase-1 classes only. Stateless; all evidence comes from the Graph snapshot.
ProseContradictionChecker
Prose contradiction pass — ADR-0002 phase 2. The bucket classes contradiction (cross-source, doc↔doc) and self-contradiction (reflexive: one file asserting ≥2 objects for the same slot). Index-free — prose triples don’t need the kuda index, so this runs on every claim set, not just when [check].kuda_index is configured. Warn tier: extraction is heuristic, so these report but never gate.
SemanticCandidate
One fuzzy pair the mechanical buckets can’t settle — the semantic tier’s intake list. The bucket pass keeps the mechanical-grade conflicts (canon-equal subject, different object) to itself and hands the agent only what needs understanding: near-duplicate subjects with a shared content token asserting different objects for the same relation.
UndocumentedFactChecker
undocumented-fact — ADR-0002 phase 4: reverse coverage (code→doc), warn tier. The public surface is the set of modules the index records as a dependency target — internal details nobody imports aren’t contract. A public module emits when no document in the mined set names it, matched the way the buckets match subjects (canon_subject: case, -/_, plurals and [check].aliases all fold), so mimus-core, mimus_core and an aliased spelling each count as documenting it. The haystack is document text, not extracted claims: a doc that merely lists a crate ([mimus-check-acp](…)) documents it without asserting a checkable claim — claim-level matching would flag every crate index page.
