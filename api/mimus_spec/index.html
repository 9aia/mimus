mimus-spec — the standard tier’s spec model and file-set evaluator (P-001 spike).

A standard is a declarative repo-conformance spec: a TOML (or YAML/JSON) document naming a family, the repo-name match globs it applies to, a severity, and the file set the repo is expected to carry. Whitelist semantics: anything tracked in the repo that no files/dirs entry covers is an unlisted violation.

Document resolution delegates to scarab-compose ([Composer::resolve_file]/[Composer::resolve_toml]): extends: chains and include:/${include(...)} come free, anchored at the spec file’s own directory. Merge semantics are scarab-compose’s deep_merge — scalars last-wins, arrays concatenate (child entries first), tables merge per-key.

Spike scope: the file-set tier plus the phase-2 predicate tier — [path."X"] tables (exists, contains, regex, except), the [git] namespace (untracked), and the [providers.<ns>] namespace are evaluated by Spec::check_repo. tamias: refs and unknown top-level keys still deserialize (or are ignored) without findings — the model does not deny_unknown_fields; they land in Spec::extra untouched. Unknown keys inside a path table or the git table are errors (typo ≠ silent pass).

Providers (P-002): each org tool owns a predicate namespace (lasius.*, bupha.*, …) declared as [providers.<ns>] tables. At check time the namespace dispatches to the StandardProvider registered under that ns() in a ProviderSet; an unregistered namespace degrades to a provider warn violation (provider-unavailable) — never a hard fail, since providers are optional by design. The claims table passes through to the provider verbatim: unknown keys inside it are the provider’s problem, not the spec model’s.

Repo enumeration prefers git -C <repo> ls-files (tracked files only — generated dirs like target/ never appear, so no carve-outs are needed beyond .git/ itself). When git is absent or the path isn’t a repo, a filesystem walk takes over: every file except .git/ counts, including untracked ones — the fallback is noisier by design and documented as such.

Traits§

StandardProvider
An org-tool predicate provider (P-002) — owns one providers.<ns> namespace and evaluates its claims table against a repo. Implementations may shell out to their tool’s CLI (bupha status --json-style) or inspect the tree directly; the port stays I/O-light by contract.

Functions§

check_unlisted
unlisted check against the union of a matched spec set — the composed standard. A tracked file is a violation only when no matched spec covers it; per-spec check_repo would double-report files a sibling spec legitimately whitelists. Severity is the strictest among specs; spec names the strictest spec (the violation belongs to the composition, not one pack).
load_specs
Load every spec under dir — *.toml, *.yaml, *.yml, *.json, sorted by file name for determinism. A single spec file path loads as a one-element vec.
