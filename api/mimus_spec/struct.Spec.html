Expand description

A declarative repo-conformance spec — the resolved document.

Field names mirror the TOML: match is a Rust keyword, so the repo-name globs live on repo_match via a serde rename. path collects the [path."X"] per-path predicate tables; providers collects the [providers.<ns>] claim tables (P-002); extra catches every other top-level key (extends is consumed by the composer before this point, but tamias, future namespaces, … land here).

Fields§

§family: String

Spec family name — appears on every violation for provenance (engine-compile, 9aia/base, …).

§repo_match: Vec<String>

Repo-name globs this spec applies to (matched against the repo directory’s file name). Empty = applies to every repo.

§severity: SpecSeverity

Violation severity — fail (default) or warn.

§files: Vec<String>

Required/covering file entries: exact repo-relative paths (must exist → missing when absent) or globs (coverage only — a glob with zero matches is not itself a violation).

§dirs: Vec<String>

Declared directories: must exist → missing when absent, and every tracked file beneath them is covered (whitelist). Literal paths only — no glob semantics.

§cover_dirs: Vec<String>

Coverage-only directories — whitelist tracked files beneath them for the unlisted check but never produce missing (the optional counterpart of dirs; lets a base spec name every plausible tree without requiring all of them).

§cover: Vec<String>

Coverage-only globs — whitelist tracked files for the unlisted check but never produce missing (the optional counterpart of glob files entries; keeps catch-alls like *.toml out of the required set).

§path: BTreeMap<String, Value>

[path."X"] per-path predicate tables — evaluated by Spec::check_repo. Kept as raw JSON at load time so spec authors get SpecError::Predicate (naming the offending key) at check time rather than an opaque serde error; Spec::load/parse stay forward-compatible.

§git: Option<GitPredicates>

[git] namespace predicates — untracked globs flag untracked-but-not-ignored files. Unknown git.* keys fail deserialization (deny_unknown_fields) — typo ≠ silent pass.

§providers: BTreeMap<String, Value>

[providers.<ns>] claim tables — namespace → raw claims Value, passed through to the StandardProvider registered under ns at check time. Values stay untyped on purpose: each provider owns its claims schema, and unknown keys inside a table are the provider’s problem. An unregistered namespace yields a provider warn violation, never a load error.

§extra: BTreeMap<String, Value>

Unknown top-level keys, preserved verbatim — forward-compat for tamias and namespaces the evaluator doesn’t know yet.

pub fn check_missing( &self, repo: &Path, ) -> Result<Vec<SpecViolation>, SpecError>

Declared-but-absent check only: exact files entries (no glob metachars) must exist on disk; every dirs entry must be a directory. Glob files/cover* entries are coverage-only — zero matches is not a violation.

§Errors

SpecError::Glob on a malformed files/cover pattern.

Source

pub fn check_repo(&self, repo: &Path) -> Result<Vec<SpecViolation>, SpecError>

File-set diff plus the predicate tier: declared-but-absent → missing; tracked-but-uncovered → unlisted; [path."X"] tables → predicate; [git] untracked globs → predicate; [providers.<ns>] tables → provider. check_missing/ check_unlisted keep file-set semantics — predicate and provider evaluation live only here.

Providers run against an empty ProviderSet — every declared namespace degrades to a provider warn violation. Callers holding real providers use Spec::check_repo_with.

§Errors

SpecError::Glob on a malformed files/cover/git pattern, SpecError::Predicate on an unknown path-table key, SpecError::PredicateValue on a mistyped predicate value or uncompilable regex, SpecError::Provider when a registered provider fails.

Source

pub fn check_repo_with( &self, repo: &Path, providers: &ProviderSet, ) -> Result<Vec<SpecViolation>, SpecError>

Spec::check_repo with a provider registry — the [providers.<ns>] tier dispatches each declared namespace to the StandardProvider registered under it. Runs last, after file-set + path predicates. An unregistered namespace yields a provider warn violation regardless of the spec’s own severity (providers are optional by design — degrade, never fail).

§Errors

Same as Spec::check_repo, plus SpecError::Provider when a registered provider’s check fails.
