1//! bupha-plane — the `kind="ci-job"` entity plane: hypha's
2//! [`hypha_http::EntityPlane`] port impl for the bupha↔hypha/peregrin
3//! seam (P-002, `project/proposals/proposal-0002-*.md`).
4//!
5//! bupha keeps CI *semantics* — the pure transition rules (enqueue
6//! supersede math, `all`-FIFO bound, retry budget) live in
7//! `bupha-core` and are mirrored here; this crate is the thin
8//! mechanical adapter holding entity state and dispatching `ci.*`
9//! ops. Register it on a node's kind registry like any other plane:
10//!
11//! ```ignore
12//! use std::sync::Arc;
13//! use bupha_plane::CiJobPlane;
14//!
15//! state.kinds.register(Arc::new(CiJobPlane::new().with_labels(labels)));
16//! ```
17//!
18//! - [`CiJobPlane`] — the plane: entity map + per-key pending lanes,
19//!   `ci.enqueue`/`ci.claim`/`ci.renew`/`ci.release`/`ci.complete`/
20//!   `ci.cancel`/`ci.status` ops, fence+lease bookkeeping, lazy
21//!   lease-expiry sweep, `ci-job-snapshot/v1` export/import.
22//! - [`job`] — the `kind="ci-job"` indexDoc model: deterministic id
23//!   `ci:{key}:{sha}:{attempt}`, state machine, create-time
24//!   validation (the wire is a trust boundary).
25//!
26//! Queue semantics stay in `bupha-core` (`is_valid_*`,
27//! `MAX_PENDING`, `Queue`/`QueuePolicy` — the spec this plane
28//! mirrors); distributed queue state is the entity plane itself —
29//! T-049 retired `bupha-queue-{redb,redis}` and `bupha-queue-lease`;
30//! the dev watcher keeps `bupha-queue`'s port + `JsonQueueStore` +
31//! single-box `TryClaim`/`LocalClaim`.
32
