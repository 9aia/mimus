pub fn with_watched(self, specs: Vec<WatchedRepo>) -> Self

Arm the plane with resolved fleet specs — Config::watched() output (bupha_plane::WatchedRepo). A create whose key matches a spec gets queue/runsOn/runner/context/ maxAttempts/repo overwritten with the fleet resolution — the same source the worker resolves at exec time, so indexDoc and execution can never disagree — and ref/event gated against the spec’s branch/events. This is how a webhook ingress campaign hands per-repo fleet.toml configuration to the entity plane without re-deriving it per node.

pub fn rehydrate( &self, docs: impl IntoIterator<Item = Value>, ) -> RehydrateReport

Rebuild plane state from entity-index docs — the hub’s durable hypha-sync projection is the store; this plane is the working set (T-072). Each doc is a ci-job indexDoc — the inner doc of the {id,kind,indexDoc,…} entity wrap (a wrapped doc is unwrapped when present).

State is preserved verbatim: a running job keeps its claim, fence, and leaseExpiresAt, so the lazy sweep requeues exactly the claims whose lease already lapsed and leaves live ones held until expiry — the same semantics as if the node had never restarted. pending lanes are rebuilt in enqueuedAt order (id tiebreak), matching FIFO enqueue order. Existing ids are left untouched — rehydration is idempotent and safe to re-run.

Runs outside Self::transact: it is a boot-time bulk load, not an op, and takes the write lock directly.
