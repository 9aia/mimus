CiJobPlane — the kind="ci-job" entity plane implementing hypha’s [EntityPlane] port (P-002, the bupha↔hypha/peregrin seam). Registered on a node’s [KindRegistry] exactly like peregrin’s CampaignEntityPlane:

ⓘ
state.kinds.register(Arc::new(CiJobPlane::new().with_labels(labels)));

The plane holds entity state in memory (the campaign-plane precedent — ops serialize on the owning node, so every transition is a single-threaded compare-and-set) and keeps a per-key VecDeque<entity_id> lane of pending jobs — Queue.pending with entity ids (bupha-core). Queue semantics stay in bupha-core (is_valid_*, MAX_PENDING, the supersede/retry rules this file mirrors); this crate is the thin mechanical adapter: entity state + ci.* op dispatch + fence/lease bookkeeping.

Ops (namespace ci, kind ci-job): create is ci.enqueue; ci.claim/ci.renew/ci.release/ci.complete/ci.cancel/ ci.status/ci.enqueue per the P-002 contract.
