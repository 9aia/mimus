tamias_driver_sturn

Module data 

Source
Expand description

data — one read of a repo’s sturn state per wire op.

The driver is a reader: every view/query resolves the target repo, folds every refs/sturn/wal/* log through the same pure functions the sturn CLI uses (sturn_claim::active, sturn_ask::all), and drops the result. No mutations — sturn claim/write/snap stay the write surface; this crate only needs what sturn claims/sturn log/sturn asks already show.

Repo resolution order (first hit wins) — mirrors sturn --repo plus driver conveniences:

  1. Request params — dir, root, or repo (all name the repo dir), e.g. pavo view sturn:claims --param dir=/path/to/repo.
  2. $STURN_REPO — driver-level convenience; the sturn CLI itself has no repo env var.
  3. sturn.toml’s repo.dir — config search identical to the CLI: --config-equivalent param config → $STURN_CONFIG → ./sturn.toml → ~/.config/sturn/sturn.toml. A relative repo.dir resolves against the process cwd, same as the CLI.
  4. . — the driver’s cwd (pavo inherits the user’s cwd, so pavo view sturn:claims inside a wired repo reads it).

When nothing resolves to a git repo, Snapshot::error carries the reason and every query degrades to an {"error": …} payload — the wire stays ok:true so hosts render the failure inline.
