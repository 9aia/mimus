Module ops 

Source
Expand description

Engine ops — cli.<verb> wire queries dispatch into the sturn engine lib through this binary’s own run verb: each call re-execs tamias-driver-sturn run <argv> with the request’s repo as cwd, so sturn::dispatch writes to the child’s captured stdout and never touches the serve loop’s ndjson stream — and every mutation keeps the engine’s own write-path semantics (WAL append, actor from config/$STURN_ACTOR, claim fencing).

ops answers the ops manifest as JSON — derived from the engine’s own clap tree (sturn::command), so a verb can’t exist on the CLI and be missing here: leaf subcommands flatten into dotted names (ws new → cli.ws.new), declared args become typed params (arg/opt/flag), and doc strings ride along unchanged.

Unbounded verbs (daemon, sub, bridge, mount) are deliberately not ops — they never return, so they live in surfaces instead: surface drivers (tamias-driver-cli/-mcp, the pavo-driver-kit surface layer) stream them via run. Streaming flags (diff --live, check --watch, service logs -f) are likewise excluded — the bounded form of those verbs stays a wire op.

Constants§

READ_ONLY 🔒
Read-only verbs — everything else appends WAL ops, writes files, pushes refs, or touches system state. Mutators belong behind a deliberate trigger, not ambient view polling.
SKIP_PARAMS 🔒
Params excluded from ops — flags that turn a bounded verb into a stream. The bounded form rides the wire; the stream rides run passthrough.
SURFACES 🔒
Unbounded surfaces — verbs that never return, so they can never be request/response ops.

Functions§

argv 🔒
cli.<verb> params → sturn argv (no argv[0] — run prepends it). Globals are resolved by run_verb (--repo/--config prepend here); the dotted verb name splits into the group path (ws.new → ws new). Declared params map by kind — positionals land last, in schema order.
kind 🔒
A clap arg → the manifest’s typed param kind — arg = positional, opt = --name <v>, flag = --name — the contract pavo-driver-kit’s surface layer renders args from.
manifest
The ops query/ops argv verb payload — self-describing so hosts and agents discover the engine surface without argv help. dir/root/repo/config/actor are the driver’s globals — accepted by every op, listed once on the manifest itself.
op_cmd 🔒
op_of
Is query an engine op (cli.<verb>)? Returns the verb name.
param_json 🔒
run_verb
Run one engine op by name: re-exec run in a child whose cwd is the request’s repo (same resolution the views use), and hand back {op, argv, code, stdout, stderr} as the query payload. ok:false is reserved for spawn failures — a nonzero code is the engine’s own exit status (e.g. check contested), honest data. params.actor sets STURN_ACTOR for the child — claims stay actor-scoped, no bypass around the engine’s own rules.
scalar 🔒
A wire scalar → its argv token (numbers/bools stringify).
skipped 🔒
Args that can’t ride the wire: streaming flags (above) plus clap’s own help/version actions.
values 🔒
All values of a param — arrays flatten, scalars wrap (repeatable opts like --option, multi-positionals like snap <ws>…).
verbs 🔒
(dotted name, clap spec) for every leaf verb — groups (ws, deploy, destroy, service) aren’t invocable themselves.
