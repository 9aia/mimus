Module absorb

myco absorb comments|jira|github — import work into the ledger from three sources:

  • comments — rg sweeps TODO/FIXME/HACK (any --kinds) comments at the repo root (respects .gitignore; project/, docs/, target/, myco.toml excluded). Each hit becomes a backlog item or an issue, note = file:line.
  • jira — a Jira CSV export (Issue key, Summary, Status, Priority, Assignee, Labels; header-name/case tolerant, BOM and quoted multi-line cells fine, optional columns may be absent, Epic Link/Epic Name/Parent key and Fix Version/s variants understood) → I-NNN issues, the Jira key preserved in note (jira:PROJ-123).
  • github — a GitHub issues dump (JSON array, an API {"issues": […]}/{"items": […]} wrapper, or CSV) → I-NNN issues, note = github:<number>.

Dedup is uniform: a row is skipped when its note marker (file:line, jira:KEY, github:N) already appears in any ledger item’s note — re-running an import is a no-op. Done-ish rows are skipped unless --include-done, which creates them done and files them straight into archive/. Row-level failures (unreadable records, rows without a title/key, non-object issues) collect into the report’s warnings — one bad row never aborts the file. Every source ends in one chore: absorb <source> (N items) commit.
