myco check [--fix] — validate the ledger and repair drift.

Checks: strict parses (miette-rendered spans), meta.toml counters ≥ max id per kind, duplicate ids across the ledger, dangling blocks:/links: refs, kind/dir filename mismatches, [x]/ status:done/status:cancelled items (the rule: terminal items are deleted — git keeps history), title/frontmatter id mismatches (a file whose title or H1 still carries its old ADR-0008: number), stale PREFIX-NNNN prose references (a mention in a body, title, index or handoff that no live or archived id resolves — code spans/fences and self-references are whitelisted), non-canonical emit drift, and worktree health: a project/ worktree on a detached HEAD, one sitting on a branch that isn’t project, or a branch that was never pushed — the git-side invariants the audit trail depends on.

Two severities (ADR-0002): error findings fail the gate, warning findings are reported and cost nothing. A stale prose reference is a warning, because doc-storage items are deleted when they finish — every handoff and note naming one dangles by design and no fixer can know what the author meant.

--fix applies the safe repairs — strip done items, rename misplaced files, renumber title-mismatched items (repointing index links, blocks:/supersedes refs and handoffs), reconcile counters, reattach a detached worktree, re-emit canonical — then re-analyzes; without it every finding is just reported.

Severity
How much a finding costs. Error fails the gate; Warn is knowledge for the reader and never changes the exit code — the distinction exists because some findings are by design and unfixable (a prose T-NNN naming an item that was completed and therefore removed: see ADR-0002). A gate that reds on those is a gate everyone learns to ignore.
