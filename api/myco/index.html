myco — the engine as a library. Everything that used to live in the binary lives here: the verb registry, clap tree, ops, serve/batch, views, continuity. run() is the compat CLI’s whole body; drivers (myco bin, tamias-driver-myco run) split it into parse/parse_from + dispatch — argv in, exit code out, verbs callable as dispatch(&matches).

myco — project management, grown not built. A mycorrhizal network for your agents: tasks, signals, handoffs.

Agent-first PM: markdown in project/ is canonical and human-editable; every deterministic write goes through this CLI (auto-commit per verb, --json everywhere). The skill teaches agents the verbs; myco manifest/myco schema are the self-describing surface.

Phase 6 wires continuity — handoff/resume over append-only handoffs/<ID>.md files (one per item, any kind); sepia hooks call them at session boundaries. Phase 7 lands the Jira-parity slice — epic:/ms: item metadata + grouping views, absorb importers (comment sweep, Jira CSV, GitHub dumps). P-007 makes the verb surface data: one registry table drives the clap tree, manifest, and serve/batch dispatch; [verbs] in myco.toml declares repo/user verbs.

absorb
myco absorb comments|jira|github — import work into the ledger from three sources:
adr
myco adr new|list|supersede — architecture decision records in adrs/NNNN-<slug>.md (Context / Decision / Consequences).
agentmd
The managed AGENTS.md agent-awareness block — init writes it, check validates it, org init rolls it out across registered repos.
backlog
myco backlog add|promote|list — deferred items in BACKLOG.md.
batch
myco batch — the one-shot serve (P-004): NDJSON verb requests in (stdin or --file), one JSON-RPC 2.0 response line out per request, each dispatched through the same [serve::Server] surface myco serve exposes — the whole verb set without holding a pipe open.
board
The board chrome — the columnar card renderer behind myco view’s board format (repo- and index-sourced alike).
cfgverb
Config-declared verbs — [verbs.<name>] in myco.toml (P-007). myco <name> resolves a config verb (layered repo<user, builtins win collisions); alias bakes argv for a read-only builtin; view-emit evaluates a ViewSpec into one of the emit shapes. Mutations stay builtin — both kinds are read-only by construction.
check
myco check [--fix] — validate the ledger and repair drift.
commit
myco commit — stage + commit worktree changes with a conventional message. Git identity comes from the repo config, like every other myco commit.
confirm
Interactive confirmation for destructive verbs — a tty prompt gated by --yes/$MYCO_YES. Scripts, agents, --json pipes, and the wire surface (serve/batch) never block: they either pass --yes or simply aren’t a terminal.
continuity
myco handoff / myco resume / myco interrupt — the continuity trio. At session end handoff appends a ## <today> · <actor> entry plus note to handoffs/<ID>.md (append-only, one file per item, uniform across kinds). At session start resume emits the minimal restart context — the item, its blocks: dep titles, the latest handoff entries, the open checklist — sized for a prompt, the single-item counterpart of status --prompt. interrupt is the abnormal end: a work-state item (claimed/in-progress/blocked) reverts to open and gets an interrupted handoff in one commit.
digest
Ledger scans + counts — the shared read path for the view verbs (status, view, report, index rebuild, org).
discover
Re-export — lives in myco_ops::discover so other front-ends (myco-driver) share it. discover itself is cli-local: ops takes the config loader as a parameter and the composition root (this crate) names the impl, so call sites stay two-arg.
done
myco done list — the DONE.md archive read. Terminal tasks (done and cancelled) leave TODO.md but stay here, filterable like every other list.
indexcmd
myco index add|remove|list|rebuild — the derived-cache registry verbs.
init
myco init — orphan project branch (plumbing, never checkout --orphan), git worktree add project project, canonical scaffold, project/ into the parent .gitignore, the managed agent-awareness block into AGENTS.md.
issue
myco issue new|list|resolve|archive|comment — one md file per issue under issues/ (archived files in issues/archive/).
itemcmd
myco item show|set — the kind-agnostic item verbs: locate an item anywhere in the ledger; mutate metadata, with --status going through the transition machine only.
items
Shared plumbing for the item verbs — the clap flag structs (--pri/--owner/…, --status/--label/--limit, --body/--text) that parse into myco_ops::items / myco-core types. The ops layer itself is re-exported so call sites read items::X for either.
links
links — the md-grammar half of the link index (P-005).
migrate
myco migrate — bring legacy ledgers to the v2 schema.
movecmd
myco item move — the cross-repo transfer. The item is re-created in the destination ledger’s own id sequence (kind, title, body, pri/owner/#label/epic/ms carried; blocks:/links: dropped — they name source-ledger ids), both ledgers get a provenance handoff (moved from/moved to), then the source walks to done: a file-backed item keeps its file with status done; a task’s line leaves the ledger and its handoff file drops to handoffs/archive/ — the check-prescribed home for items that are gone. Two commits, one per worktree, both under the usual --no-commit/$MYCO_NO_COMMIT rules.
next
myco next — the single highest-priority open item: “what should I work on” (I-020, falls out of P-006). It’s a view eval with limit = 1 — the filter flags are view’s [FilterFlags] merged over an open tasks+issues default. --claim is the only new surface: it mutates the emitted item to claimed + an owner in one per-verb commit.
ops
Re-export — lives in myco_ops::ops so other front-ends (myco-driver) share it. store_at is cli-local: the concrete MdStore factory — myco-ops is generic over myco_store::Store, so the composition root (this crate) names the impl.
org
myco org — cross-repo scaffolding; cross-repo views are index-sourced myco view specs (view org-board / view org-status, --source index).
plan
myco plan new|list — execution plans in plans/pl-NNNN-<slug>.md with a phase checklist.
proposal
myco proposal new|list|status — design proposals in proposals/proposal-NNNN-<slug>.md.
reap
myco reap — the bulk stale-claim reaper. A scheduler (peregrin campaign, a cron’d myco batch) calls it periodically: every live claimed/in-progress item whose last activity — the latest handoff entry’s date, else created — is older than --idle-days (default report::STALE_CLAIM_DAYS, the same threshold report’s stale-claims finding uses) reverts to open with an interrupted handoff — exactly myco interrupt <ID>, batched: per-item failures are collected, the rest still land, and the whole sweep is ONE commit (chore: reap N stale claims). --session <id> scopes to items whose claim tag names that session (the continuity::claim_session rule interrupt --session uses); --dry-run lists the sweep with zero writes.
redo
myco redo — restore the commit the last undo moved away from. Pops the undo journal (<git-common-dir>/myco-history.json) and git reset --hards to its target; repeatable while entries remain and HEAD still matches each entry’s anchor.
registry
The single verb registry (P-007) — one VERBS table drives all three front-ends: the clap command tree (command, builder mode, no derive), manifest().verbs/implemented (manifest_verbs), and serve/batch dispatch (crate::serve::Server::dispatch). A verb can’t exist on one surface and not the others: cli/wire handlers share one params schema — the wire schema and the CLI surface are one declaration decoded into the same Args bag.
report
myco report — aging + velocity + blocked, the “how is the ledger trending” view.
schema
myco schema — the file/state spec as machine-readable JSON.
serve
myco serve — a sequential request/response verb surface for embedding: an orchestrator (peregrin) spawns one long-lived process per repo instead of one spawn per verb. A single process serializes writes — no index.lock races — and the store is re-opened per request, so the served process always sees on-disk truth.
status
myco status [--prompt] — the ledger digest; THE agent-context verb. Human output is compact counts + the in-progress and blocked lists; --prompt is a token-sized block (repo, counts one-liner, then items grouped in-progress → blocked → claimed → open-by-priority, one per line, no prose); --json is the structured digest — with --prompt it’s {"prompt": "<block>"}.
sync
myco sync — reconcile the ledger branch with its remote.
templates
Item-file body templates — embedded format! strings, not a templating engine. Four kinds, four static skeletons; pulling in minijinja + a myco-template crate would add a dependency for nothing these can’t do. Revisit when templates grow variants (epics, milestones).
todo
myco todo add|done|defer|list — task items in TODO.md.
undo
myco undo — rewind the project branch tip one commit. Every mutating verb is one commit, so the reset is the inverse mutation; the undone commit is recorded in the undo journal (<git-common-dir>/myco-history.json) for redo. --list shows the redoable stack without mutating.
view
myco view [NAME] — declarative views (P-006): named presets from [views] config + built-ins, or an ad-hoc spec from flags. One engine: filter → group → sort → limit → format. Read-only — the write path stays item set/todo/issue.

Functions§

dispatch
One parsed command line → exit code. The dispatch every driver shares; argv parsing is a caller concern.
parse
Process argv → parsed matches. Split from dispatch so drivers can parse their argv (a run verb, a re-exec) without owning process args. Clap errors/help still exit the process, same as argv parsing.
parse_from
Same, from an argv iterator — parse_from(["myco", "board"]).
run
The compat CLI body — parse argv, dispatch, hand back the code. sigpipe::reset restores conventional-Unix SIGPIPE behavior (die silently on EPIPE) — println! would otherwise panic when piped to a reader that closes early (myco board | head).
run_from
Same, from an argv iterator — the run passthrough entry every driver re-execs (tamias-driver-myco run <myco argv>).
