myco index add|remove|list|rebuild — the derived-cache registry verbs.

add validates the repo has a project/ worktree (same rules as discovery), registers it, and takes a first snapshot. rebuild re-scans via MdStore and re-keys the snapshot on the project-branch HEAD — freshness afterwards is the trivial stored head == current head check org does before trusting a snapshot.

Functions§

current_head
Freshness check — the entry’s registered worktree HEAD (--dir/project_dir worktrees don’t live at <root>/project). None when the worktree is gone or has no HEAD. Used by index list and org’s auto-rebuild.
h_add
The index add verb — registers the repo and takes a first snapshot when it has a ledger. A git repo with no qualifying project/ worktree registers as ledger = "none" (the org pattern’s explicit ledger-less state) with no snapshot; --org marks the repo the org/global ledger instead — the fallback target discovery resolves ledger-less members to — and clears the mark on every other entry (at most one).

par_map
Map items across scoped worker threads, preserving order — for the per-repo git/fs calls that dominate org/index latency. Keep redb I/O out of f: the index locks per open.
repo_at
<path> → the repo root + project worktree. Accepts a repo root (<path>/project must qualify), the worktree itself, or — for index add’s ledger-less path — any dir inside a git repo (the returned worktree is the conventional <root>/project, which may not exist; callers check discover::qualifies). --dir discovery doesn’t qualify its path, so the check is repeated here — index add on a plain dir must fail.
scan_one
