myco-store-md — the markdown impl of [myco_store::Store], and the owner of the project/ file spec. Strict parse (spans on every error), canonical emit (byte-identical for the same model, emit → parse → emit fixed point).

§The grammar

TODO.md      # TODO — <repo> · ## <section> · - [ ] T-NNN <title> · <tokens>
BACKLOG.md   # Backlog · ## <section>? · - T-NNN <title> · <tokens>  (deferred)
meta.toml    name = "<repo>" · [next] t|i|p|adr|pl = <n>
<dir>/<file> +++ <toml frontmatter> +++ · <markdown body>
index.md     verbatim passthrough (generated views land later)

Item-line tokens (·-separated, after the title): status:, pri: (low|med|high|crit), owner:, created: (YYYY-MM-DD), #labels, blocks:T-NNN[,…], links:T-NNN[,…], epic:<name>, ms:<name>, note:<free text> (the dedup/provenance slot absorb fills). Canonical order is that order; defaults (status:open/deferred, pri:med, unset owner/created/ labels/blocks/links/epic/ms/note) are omitted.

Engine: markdown (wooorm markdown-rs) parses everything to mdast for structure + spans. Emit is canonical, hand-written line layout; mdast_util_to_markdown provides inline escaping, verified by re-parse with a local escaper as fallback — 0.0.2’s escaper can’t emit GFM [ ] checkboxes and corrupts sequences like · #_x (byte/char index drift).

Item files: issues/issue-NNNN-slug.md, proposals/proposal-NNNN-slug.md, adrs/NNNN-slug.md, plans/pl-NNNN-slug.md — +++ TOML frontmatter + verbatim body.

Handoff files: handoffs/<ID>.md — one append-only file per item (any kind): +++ item +++, # Handoffs — <ID> title, ## <date> · <actor>[ · session:<id>] entries + verbatim notes; handoffs/archive/ holds files whose item was removed.

frontmatter_id
id = "…" pulled out of a closed +++ frontmatter block — the cheap probe for when the strict parse isn’t needed (or already failed). None for files with no +++ fence, no closing fence within [FRONTMATTER_PROBE_MAX] lines, or no parseable id line — including frontmatter-less files that merely borrow an id number via their filename. The close requirement is what keeps a body’s id = "…" (a code block, a quoted example) from posing as frontmatter.

repair_frontmatter
Rewrite a leading --- YAML frontmatter block as the canonical +++ TOML fence — the repair half of parse_item_file’s strictness. Agents hand-authoring item files reach for the ubiquitous --- + key: value convention; this converts the simple subset — top-level key: scalar, key: [a, b] inline lists, # comments, blank lines — and returns the source with a +++ fence, still unvalidated: callers re-parse. None when the file doesn’t open with a closed --- block, the block exceeds [REPAIR_MAX] lines, or a frontmatter line isn’t key: value at column 0 (nested maps, - list items — shapes this doesn’t claim to understand).
write_atomic
