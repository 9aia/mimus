tamias-core — pure domain + the bundle engine for the package/content manager.

I/O-free types: package identity (@scope/name@semver), the ref grammar, manifests, install records, and digests. Plus the artifact engine the store and sources share: tar pack/unpack, the include: deep-merge overlay, and payload walking. Ports and adapters live in the sibling crates.

Modules§

archive
Tar archives — bundle pack writes .tgz; the http/fs sources unpack tarballs here. Paths sanitize on unpack (no absolute/.. escapes), the executable bit keeps.
atomic
Atomic file writes — a same-dir tmp file, fsync, then rename(2). A crash can leave a stray *.tmp sibling but never a torn file at path. Mirrors myco-store-md’s write_atomic.
digest
SHA-256 helpers + payload walking — the content addressing the store and verify use.
error
Engine failures — filesystem operations carry context; everything else is a message.
identity
Package identity — [@scope/]name@version.
manifest
tamias.{yaml,yml,toml} — the package manifest. YAML is preferred when several exist; TOML stays the fallback.
overlay
include: overlay composition. A payload deep-merges over its bases: local wins, dicts merge per-key, arrays concat local-first. Earlier include: entries outrank later ones. Conflicting .yaml/.yml/ .json files merge document-wise; other files resolve whole-file with the higher priority winning.
process
Bounded subprocess execution — Command::output blocks forever on a hung child (a stalled git remote, a wedged driver), so callers that can be reached by untrusted refs go through output_with_timeout.
project
The project lockfile — tamias.lock (YAML) pins resolved identity, source ref, and digest for reproducible installs.
records
The install record — the provenance a store entry carries and list/info/verify report on.
