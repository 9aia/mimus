Expand description

bupha — “the oxpecker on your repo’s back”: a headless CI engine. Pluggable sources (forge webhook, sturn WAL poller) land pushes on the queue, the queue batches them latest-wins, a pluggable runner executes each sha, and status sinks report. No server, no UI.

Dev/debug harness (ADR-0006 amendment): deployed fleets run this same engine through tamias-driver-bupha host under tamias provider units. The verbs below (watch, run, doctor, import, deploy/destroy/service helpers, agent fleet daemons) exist for local reproduction, standalone/dev-mode operation, and migration. There is no bupha binary — the command ships as the libraries/bupha tamias pack’s bins[] shim → tamias-driver-bupha cli → run_from (T-012).

The lib surface (Cli/command()/parse_from()/run_from()) is what tamias-driver-bupha’s ops manifest derives from — the “CLI-as-generated-surface” contract (P-021): every bounded verb is reachable as a cli.<verb> wire query, unbounded daemons (watch/agent/gha-runner) ride surfaces.

Config: bupha.yaml/.yml/.toml (secrets come from env). See bupha-core::Config.

command
The clap verb tree as a [clap::Command] — the ops manifest (tamias-driver-bupha ops) derives itself from this, so a verb can’t exist on the CLI and be missing from the driver’s wire surface.
parse
Process argv → a parsed Cli. Split from [dispatch] so drivers can parse their argv (a run verb, a re-exec) without owning process args. Clap errors/help still exit the process, same as argv parsing.
parse_from
Same, from an argv iterator — parse_from(["bupha", "runs"]).
run
The compat CLI body — parse process argv, dispatch, hand back the exit code. Most verbs std::process::exit inside their handlers on failure and return () on success; run_from reports 0 for those paths.
run_from
Same, from an argv iterator — the run passthrough entry tamias-driver-bupha re-execs for cli.<verb> ops (tamias-driver-bupha run <bupha argv>).
