tamias-deploy-windows — the deploy port’s Windows adapter: manage a per-user scheduled task through schtasks.exe (Task Scheduler). No admin needed: tasks register under the interactive user with RunLevel=LeastPrivilege.

A ServiceSpec renders to two artifacts under the task dir (%LOCALAPPDATA%\tamias\tasks by default):

  • <name>.cmd — a generated batch wrapper that applies the spec’s environment (env_file via for /f, inline env as set lines, inline winning — systemd’s order) and cd /ds to workdir before exec’ing the argv. Task Scheduler actions cannot carry env vars, so the wrapper is how env reaches the process.
  • <name>.xml — the task definition imported via schtasks /create /xml … /f: a LogonTrigger (the honest analog of a systemd user unit starting at login), InteractiveToken principal, and settings tuned for a long-running service (ExecutionTimeLimit=PT0S — the 72h default would kill daemons; battery blocks off; RestartOnFailure mapped from restart).

§Honest gaps

  • Restart count is capped. systemd’s on-failure/always retries forever; Task Scheduler’s RestartOnFailure takes a Count of 1–255 — we emit 255 and document the cap. restart="always" also can’t restart on a clean exit(0) — RestartOnFailure only fires on failure, so always degrades to on-failure semantics. restart_sec maps to Interval, clamped up to the schema minimum of PT1M.
  • env_file is read by for /f, not by the OS: only K=V lines and # comments are understood; systemd-isms like export K=V, quoting, and variable expansion are not.
  • No journal. status/logs are best-effort schtasks /query output — Task Scheduler keeps no per-task log; capture service logs inside the payload (or a provider.health.cmd) instead.
  • stop is schtasks /end — it terminates the process tree root, not necessarily grandchildren the way systemd’s cgroup kill does.
  • Real schtasks.exe execution is #[cfg(windows)]-gated (SchtasksRunner only exists there); everywhere else WindowsDeploy::new installs an unavailable runner so verbs fail loudly instead of shelling out. Tests inject a Runner recorder on any platform.

render_task_xml
Render the Task Scheduler task XML — a LogonTrigger (per-user service ≈ start at logon), InteractiveToken + LeastPrivilege principal (no admin), service-tuned settings (ExecutionTimeLimit=PT0S — the 72h default would kill daemons — battery blocks off, RestartOnFailure from restart/ restart_sec), and an Exec action running cmd.exe /d /c on the wrapper .cmd.
render_wrapper
Render the wrapper .cmd — env first (env_file via for /f, then inline env overriding, systemd’s order), cd /d to workdir, then the quoted argv, then exit /b %errorlevel%.
