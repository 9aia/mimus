bupha-watch — the watcher engine host, shared by bupha watch (dev CLI) and tamias-driver-bupha host (deployed provider units, ADR-0006: units exec the driver binary, not a cargo-installed bupha).

watch(cfg) runs the same pipeline bupha watch always has: trigger listener (forge webhook and/or sturn WAL poller) → latest-wins queues → per-job runner → status sinks, with the dev/test WorkQueue port (production distribution is the ci-job entity plane). The shared builders below (build_runner, build_sinks, run_job, settle_run, …) are also what the CLI’s agent/run commands and the driver’s worker verb wire — one implementation, no duplication.

Config arrives already loaded (bupha_core::Config); secret values resolve through the same chain the CLI uses — env → cuora → OS keyring → ~/.config/bupha/env (cuora canonical per T-056) — by NAME only.

Standalone/dev mode (ADR-0007): the trigger-listener path (trigger.kind forge webhook, [trigger.sturn] poller) is the fallback ingress for deployments with no peregrin. Production webhook/forge ingress is a peregrin campaign listener that normalizes deliveries through bupha’s Trigger semantics and enqueues ci-job entities via ci.enqueue — the engine bits below (queues, runners, sinks) stay canonical either way.
