Module entity_worker 

Source
Expand description

The ci-job entity-plane worker (P-002 §4.1) — polls kind="ci-job" entities on a hypha/peregrin node and runs them through the same run_job pipeline; used by tamias-driver-bupha worker. entity_worker — the ci-job consumption loop (P-002 §4.1): the entity-plane replacement for the retired redis WorkQueue pull path (T-049).

One worker process polls EntityApi::list_entities("ci-job"), filters pending jobs this box can run (known key + runsOn ⊆ [worker] labels), CAS-claims via ci.claim, executes through the same run_job pipeline every other host uses (worktree → runner → status sink), renews the lease on run_job’s ticker, and settles with ci.complete. Claim loss (409 fence mismatch) abandons the run — a peer owns it; a cancelRequested flag on the entity kills the child and settles cancelled.

The loop is split into a narrow synchronous [JobApi] port (so the state machine unit-tests against an in-memory fake) and [EntityJobApi], the hypha_node_api::EntityApi adapter that bridges the async trait onto a current-thread tokio runtime — HttpEntityApi is blocking-ureq inside spawn_blocking, which needs a runtime context bupha otherwise doesn’t carry.

EntityClaim
TryClaim over a held entity claim — run_job’s renew ticker speaks this trait; every call maps onto ci.renew. try_claim/ is_done/mark_done are single-box no-ops here: the entity CAS already happened and there is no peer-done set to consult.
EntityJob
A ci-job entity as the worker sees it — the wire id (ops target it verbatim) plus the parsed indexDoc.
EntityJobApi
JobApi over hypha_node_api::EntityApi — the production impl (HttpEntityApi against a hypha/peregrin node; any other EntityApi impl works too, e.g. a hub’s SyncEntityApi).
HeldClaim
A won ci.claim — every holder op (renew/release/complete) must echo worker + fence; a mismatch is a 409 = claim lost.
WatchExec
Production executor — the same wiring bupha watch uses: per-key status sinks, per-key runners, telemetry/attest/audit, one shared child slot (one build at a time per box). Queue persistence does NOT apply — entity state is the queue.
