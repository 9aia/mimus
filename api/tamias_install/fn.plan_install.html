tamias install --plan — the dry-run half of [install_inner]: parse → plan → fetch-or-cache → manifest, then report instead of act. include: entries are classified ([include::plan_include]), never resolved — no recursive installs, no overlay, no composed digest. Driver work stops at resolution ([tamias_driver::find_driver] may capabilities-probe discovered drivers — trusted local binaries, 10s timeout); bundled-driver registration, dispatch, and the store commit never run.

Trust/signature are computed exactly as install does, except a would-be tamias_sign::enforce_signature failure is captured in InstallPlan::problems — a dry-run shows “this would fail” instead of hiding it or refusing to plan.

§Errors

Fails on an unparseable ref, a planning/fetch failure, a missing or invalid package manifest, an unreadable store, or an I/O-level digest/driver-listing failure. Would-be install failures land in InstallPlan::problems instead.
