Expand description

One runnable job after matrix fan-out, ${{ }} interpolation and needs resolution. Indices in needs point into the slice this job came from (the workflow’s expanded, topo-ordered list).

Fields§

§workflow: String

Workflow display name (for logs).

§id: String

The job’s YAML id — the handle needs.<id>.outputs.* expressions reference (not name:/label).

§label: String

name: or the job id.

§runs_on: Vec<String>

Labels GitHub would schedule on (recorded; execution is always local).

§needs: Vec<usize>

Indices of jobs that must pass first (same-workflow only).

§env: Vec<(String, String)>

Workflow + job env merged (last wins), values interpolated.

§working_directory: Option<String>§shell: Option<String>§outputs: Vec<(String, String)>

outputs: — name → interpolated template. needs.*/steps.* refs inside survive as literal ${{ … }} for the renderer, which resolves them against collected step outputs once the job has run.

§cond: Option<Cond>

if: — parsed + folded (env/github/matrix resolved, needs/ steps refs deferred). None → the implicit needs gate.

§timeout_seconds: Option<u64>

timeout-minutes in whole seconds — the renderer enforces it with a watchdog around the job body.

§fail_fast: bool

strategy.fail-fast (default true with a matrix): after a leg of this job id fails, remaining legs are cancelled.

§max_parallel: Option<u32>

strategy.max-parallel — honored as a logged no-op; legs still run sequentially.

§steps: Vec<Step>
