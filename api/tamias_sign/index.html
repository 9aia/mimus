tamias-sign — optional content signing for published packages, via ssh-keygen -Y sign/-Y verify (the same mechanism sturn uses for its WAL ops; SSH signing is stdlib tooling — Ed25519 under the hood, no new crypto deps).

What is signed. The canonical payload is the package’s provenance anchors — name, scope, version, and the sha256: digest of the unpacked payload tree (tamias_core::dir_digest):

tamias-package-v1
name: <bare name>
scope: <scope | ->
version: <version | ->
digest: sha256:<hex>

The digest is the same value the registry index records and the store record carries, so a signature binds “this exact payload, under this name@version” — tampering with either side fails verification. See signing_bytes.

Transport. Signatures ride the registry index: publish --sign stores the armored PEM in the entry’s signature field, which index.json carries to every cf:/registry install. Installed entries keep it in the store record so tamias verify can re-check.

Boundary (v1). Only registry-published packages (cf: refs) can carry a signature — a signature can’t live inside a git: or bare https: ref without a sidecar convention, so those verify by digest-pin alone. signing.required therefore effectively mandates registry-published packages. cosign/OCI signing is future work — it needs its own binary + identity model.

Secrets. The private key is only ever a path — resolved from --key, $TAMIAS_SIGNING_KEY (whose value is a path), signing.key_env’s named env var, or signing.key. Key material never appears in config, args, or logs.

Constants§

ALLOWED_SIGNERS_ENV
Env var naming an allowed_signers file — wins over signing.allowed_signers (the env-wins rule the config’s store/cache/registry resolution follows).
DEFAULT_NAMESPACE
The ssh-keygen -Y namespace signatures are made under — a signature minted for tamias-package can’t be replayed as another namespace’s (sturn uses sturn-event the same way).
OFFICIAL_SIGNERS_ENV
Env var whose value is an official_signers file — the smaller trust set backing the official-badge check (P-005). Wins over signing.official_signers, same env-wins rule as ALLOWED_SIGNERS_ENV.
SIGNING_KEY_ENV
Env var whose value is the signing-key path — checked before signing.key_env/signing.key on publish --sign.

signature_status_detail
signature_status plus which principal verified — the @scope/name or bare name allowed_signers line whose key checked out (None unless the status is SignatureStatus::Verified). signing_bytes
Canonical bytes for signing — the provenance anchors, one key: value per line, - for absent optional fields. Fixed order, no trailing ambiguity; both sides build it from the same inputs so it can’t drift.
trust_and_signer
trust_tier plus the verified signing principal in one pass — the @scope/name or bare name that checked out (official set preferred), None for unsigned/failed tiers. The install pipeline records both on the StoreRecord.
trust_tier
The package’s TrustTier — reporting only; the install gate stays enforce_signature. source_ref is the ref the install was invoked with (pin detection reads it verbatim); digest is the payload digest the signature bound.
verify
Verify signature (armored PEM) over bytes against the allowed_signers file — ssh-keygen -Y verify -I <principal>. principal selects the allowed_signers line; tamias uses the bare package name, so a key authorized for ci-gate can’t vouch for other-pkg.
