tamias — the engine as a library. Everything that used to live in the binary lives here: the clap tree, every verb’s dispatch, the Env roots, the bin/driver/serve machinery. The tamias binary (src/main.rs) is a thin compat wrapper over run; tamias-driver-tamias consumes command/run_from for its pavo ops surface (cli.<verb> wire queries + run/cli passthroughs — the P-021 generated-surface pattern).

P2b: the distribution verbs over the source port, the content-addressed cache, and the local store. PL-008 added the operator surface for the provider model: drivers (discovery + capabilities), provider list (installed provider: blocks), run/logs (foreground exec + journal over provider services), and service/deploy/uninstall for the per-user units/tasks/agents they render (systemd / launchd / Task Scheduler by platform).

Unlike the sibling engines (myco/lasius/sepia), the tamias bin itself is not a bins[] shim target: every shim in the org execs tamias bin exec, so tamias must stay a real binary on PATH — the substrate can’t retire its own helper. The ops surface still rides tamias-driver-tamias for pavo embedding.

command
The engine’s clap tree — the self-describing surface drivers derive their ops manifest from (tamias-driver-tamias ops).
run
The compat CLI body — parse argv, dispatch, hand back the code. sigpipe::reset restores conventional-Unix SIGPIPE behavior (die silently on EPIPE) — println! would otherwise panic when piped to a reader that closes early (tamias list | head).
run_from
Same, from an argv iterator — the run/cli passthrough entry every driver re-execs (tamias-driver-tamias run <tamias argv>). 0 on success, 1 on error — the compat bin maps it back onto ExitCode.
