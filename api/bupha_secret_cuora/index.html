Cuora impl of Secrets — the canonical secrets story (T-056).

Each bupha secret NAME resolves to a fixed cuora ref: cuora://bupha/<NAME> — e.g. BUPHA_WH_9AIA_BUPHA maps to cuora://bupha/BUPHA_WH_9AIA_BUPHA. Values are fetched through the cuora CLI (get/put) so audit events, guardrails, and vault policy apply exactly as for every other consumer; bupha never stores a value itself.

get shells cuora get per lookup. Secrets resolve once at watcher/driver boot (a handful of names per fleet), so a per-call process is cheaper than a persistent cuora serve session and needs no shared mutable state. A missing cuora binary, a denied op, or an absent ref all answer None — “not here” — so the caller’s chain falls through to the legacy stores exactly like a keyring miss on a headless box.

Env knobs: BUPHA_CUORA_BIN overrides the binary path (tests stub it); CUORA_* and --config resolution stay cuora’s own. CUORA_ENV/--env picks the vault env — bupha does not pin one.
