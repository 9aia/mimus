Typed item ids in one namespace — T-012 tasks, I-003 issues, P-002 proposals, ADR-0004 ADRs, PL-001 plans, plus user kinds declared via [[kinds]] (P-008).

ItemKind is the id identity — the prefix the id grammar carries (T, ADR, a user’s S). It’s Copy data, not a closed enum, so ItemId parsing/serde needs no kind table: any [A-Z][A-Z0-9]* prefix is grammatically valid. Whether a prefix is declared — and the metadata behind it (name, storage, states) — lives in crate::KindTable; check and the store resolve through it.

Ordering is declaration order for the five builtin kinds, then prefix-alphabetical for user kinds — a pure function of the prefix, so BTreeSet<ItemId> stays consistent without a table.
