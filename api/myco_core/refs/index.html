refs — the pure edge scanner behind the link index (P-005).

Every project/ file contributes a set of Edges, always with src = the item the file speaks for: blocks:/ supersedes:/superseded_by:/links: frontmatter declares edges verbatim, X-NNN tokens in prose become references edges, and a handoffs/<ID>.md filename is a handoff edge (a filename fact — callers record it, nothing to scan).

The index stores these forward edges plus a reverse table, so blocked_by/referenced_by/superseded_by appear only as mirrored kinds in query results — a file never declares an incoming edge. Frontmatter edges are kept as declared (self-blocks are the ledger’s problem); mention self-hits are dropped — quoting your own id isn’t a link.

Bounds (the proposal’s “bounded GC”): bodies scan at most MAX_SCAN_BYTES and emit at most MAX_MENTIONS reference edges, so one pathological file can’t blow up the index.

Structs§

Edge
One directed edge src → dst — the unit extract emits and the index stores. Ord sorts (src, kind, dst) for deterministic output.

Enums§

EdgeKind
The relationship an Edge asserts between two items. The *_by forms are the reverse views — extract only ever produces Handoff, Blocks, Supersedes, SupersededBy, Associated, and References; the index materializes the mirror at query time.

Constants§

MAX_MENTIONS
The most references edges one extract emits.
MAX_SCAN_BYTES
The most body text one extract scans — 64 KiB. The cap applies to the byte window, not to items: a file is still scanned per-item, so every item gets its own 64 KiB.

Functions§

extract
The edges one file (or file section) declares for id — frontmatter links plus X-NNN mentions in body. meta is None for files without item frontmatter (handoffs); id is always the item the file speaks for (the caller resolves it — from frontmatter, filename, or ledger position).
mentions
X-NNN id tokens in text — T-001, I-003, P-002, ADR-0004, PL-001, plus any ≤3-char uppercase prefix a user kind might declare (P-008 — the scan is grammar-level; extract drops undeclared prefixes via the kind table). Deliberately not markdown-aware: a token in a code fence counts the same as one in prose (v1 deliberately over-counts rather than teaching the scanner the grammar). Sorted, dedup’d, bounded by MAX_SCAN_BYTES / MAX_MENTIONS; malformed candidates (T-0, overflow numbers) fall through ItemId’s own parser.
