tamias-driver-mimus — the pavo view driver for a repo’s mimus critic state.

Verbs (the tamias driver contract):

  • manifest — print the [DriverManifest] JSON (discovery probe; never touches repo state).

  • capabilities — {"capabilities": ["pavo"], "verbs": […]}.

  • ops — the engine ops manifest: every mimus CLI verb as a cli.<verb> wire query, derived from the engine’s own clap tree ([mimus::command]).

  • run <argv> — engine passthrough: tamias-driver-mimus run audit ≡ mimus audit. Also the child side of cli.* wire queries (ops::run_verb re-execs this same verb so engine output never touches the serve stream).

  • serve — ndjson JSON-RPC on stdio: {"op":"manifest"}, {"op":"views"}, {"op":"view","view":…,"params":{…}}, {"op":"query","query":…,"params":{…}} → {"ok":true,"result":…} / {"ok":false,"error":…}. query:"ops" answers the ops manifest; query:"cli.<verb>" runs the engine op.

  • cli <mimus argv> — the tamias bins[] shim verb (P-021): tamias bin exec runs tamias-driver-mimus cli --dir <pkg> --name mimus <argv> for a declared shim: cli bin; the two driver flags are stripped and the rest goes to mimus::run_from with inherited stdio — full engine parity (--config globals before the verb, --help, stdin-bound verbs, the unbounded surfaces should mimus grow any).

Optional surface: feature mcp embeds pavo-driver-kit’s surface layer — mcp serves the ops as MCP tools on stdio, equivalent to the standalone tamias-driver-mcp surface driver, minus the PATH/discovery hop.

Which repo: each view/query resolves its own target — params.dir/params.root/params.repo/params.config → $MIMUS_CONFIG → <dir>/mimus.toml → ~/.config/mimus/mimus.toml, exactly the mimus CLI’s config search; the repo root is the config’s parent dir. See data.rs for the exact order. Engine ops are the exception by design: cli.<verb> re-execs run in the resolved dir and lets mimus::dispatch own the outcome — writes keep the engine’s own semantics (config search, .mimus/ cache, claim rewrites). manifest/views are repo-free so pavo can enumerate drivers anywhere.

The view side is read-only: it reads mimus.toml, rules/*.toml, and .kuda card provenance in-process, and shells out to mimus report --format json for the violations view — mimus owns the check pipeline; the driver only ever reads its output.

One parsed wire [Request] → response. The kit’s serve loop owns the ndjson plumbing and turns parse failures into ok:false; ops this driver doesn’t implement (render, submit, jobs, notifications) get the same ok:false convention every non-provider driver answers.
engine_argv 🔒
cli verb argv (after the cli token) → engine argv (argv[0] included). tamias bin exec/driver exec prepend the standard driver flags — --dir <payload> --name <pkg> — which the engine doesn’t know; consume the leading run of those two (--flag v and --flag=v forms) and pass everything else through untouched. --config is deliberately NOT stripped: it’s a mimus global, so a user-passed one must reach the engine’s own parse.
