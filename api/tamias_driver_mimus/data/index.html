data — one read of a repo’s mimus state per wire op.

mimus is unusual among the 9aia tools: it keeps no persistent state. There is no ~/.local/share/mimus, no verdict log, no history — mimus.toml plus the repo’s own sources are the state, and every mimus verb recomputes on read. The only on-disk artifacts are caches: .mimus/triples.db (prose-triple extraction cache, ADR-0002 ph3) and the kuda index the symbol/ graph checkers read ([check].kuda_index).

So this driver’s “snapshot” is resolution, not loading:

  • mimus:status, mimus:rules, mimus:audit read in-process — config via mimus-config’s FileSource (the same source the CLI uses), rules via mimus-rules::load_rules, card trust scores via the same .kuda/modules/*.yaml provenance-hash walk mimus audit performs.
  • mimus:violations is the expensive op: it shells out to mimus report --format json (the full check pipeline — claim extraction, fs/cmd/symbol checkers, rules, graph buckets). Reimplementing that pipeline here would fork the critic; the CLI is the authority.

Root/config resolution mirrors the mimus CLI exactly (mimus-cli/src/main.rs root() + mimus-config’s FileSource):

  1. Request params — config names a config file directly; dir/root/repo name the repo dir the config search starts from (the CLI’s ./mimus.toml becomes <dir>/mimus.toml).
  2. $MIMUS_CONFIG — same env var the CLI honors.
  3. <search-dir>/mimus.toml — ./mimus.toml for the CLI.
  4. ~/.config/mimus/mimus.toml — the global fallback.

The repo root is the config file’s parent directory (the CLI’s root()), or ./the dir param when no config exists — the same place mimus audit/mimus doctor would look.

(dir, config) for an engine-op child — the resolution load uses, minus the snapshot: dir is the cwd the re-exec’d run inherits (config’s parent, else the search dir), config is the mimus.toml the child gets as an absolute --config. None config leaves the child’s own search in charge.
violations_json
Run mimus report --format json in the resolved root and parse the violations array. This is the one expensive op — everything else reads files in-process. A hard timeout keeps a configured semantic tier ([check].acp_cmd) from hanging the wire forever.
