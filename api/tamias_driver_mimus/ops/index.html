Module ops 

Source
Expand description

Engine ops — cli.<verb> wire queries dispatch into the mimus engine lib through this binary’s own run verb: each call re-execs tamias-driver-mimus run <argv> with the request’s resolved dir as cwd, so mimus::dispatch writes to the child’s captured stdout and never touches the serve loop’s ndjson stream — and every mutation keeps the engine’s own write-path semantics (config search, .mimus/ cache, claim rewrites).

ops answers the ops manifest as JSON — derived from the engine’s own clap tree ([mimus::command]), so a verb can’t exist on the CLI and be missing here: declared args become typed params (arg/opt/flag), doc strings ride along unchanged.

mimus has no unbounded verbs today — surfaces is empty by design, kept so a future streaming verb (watch mode, a serve loop) has an obvious home: surfaces never return, so they ride run passthrough, never request/response ops. Streaming flags would join SKIP_PARAMS for the same reason.

mutates is honest: check/report write .mimus/triples.db (the prose-triple cache), fix rewrites claim text, init scaffolds mimus.toml + rules/ — everything else only reads.

Constants§

READ_ONLY 🔒
Read-only verbs — init writes config, check/report write the .mimus/ triples cache, fix rewrites claims. Mutators belong behind a deliberate trigger, not ambient view polling.
SKIP_PARAMS 🔒
Params excluded from ops — flags that turn a bounded verb into a stream. None today.
SURFACES 🔒
Unbounded surfaces — verbs that never return, so they can never be request/response ops. None today.

Functions§

argv 🔒
cli.<verb> params → mimus argv (no argv[0] — run prepends it). Globals are resolved by run_verb (--config prepends here; the child cwd is the resolved dir, which is how the CLI finds its repo — mimus has no --repo flag). The dotted verb name splits into the group path; declared params map by kind — positionals land last, in schema order.
kind 🔒
A clap arg → the manifest’s typed param kind — arg = positional, opt = --name <v>, flag = --name — the contract pavo-driver-kit’s surface layer renders args from.
manifest
The ops query/ops argv verb payload — self-describing so hosts and agents discover the engine surface without argv help. dir/root/repo/config are the driver’s globals — accepted by every op, listed once on the manifest itself.
op_cmd 🔒
op_of
Is query an engine op (cli.<verb>)? Returns the verb name.
param_json 🔒
run_verb
Run one engine op by name: re-exec run in a child whose cwd is the request’s resolved dir (same resolution the views use), and hand back {op, argv, code, stdout, stderr} as the query payload. ok:false is reserved for spawn failures — a nonzero code is the engine’s own exit status (e.g. check findings), honest data.
scalar 🔒
A wire scalar → its argv token (numbers/bools stringify).
skipped 🔒
Args that can’t ride the wire: streaming flags (above), the driver-resolved --config global, and clap’s own help/version actions.
values 🔒
All values of a param — arrays flatten, scalars wrap.
verbs 🔒
(name, clap spec) for every leaf verb. Hidden plumbing (gen-cli-docs) is a docs-pipeline verb, not an engine op — it stays reachable through run passthrough.
