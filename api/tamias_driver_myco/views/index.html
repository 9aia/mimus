Expand description

views — the driver’s manifest: every ViewSpec plus the query resolvers that feed them.

Read path: all data comes from crate::data::Snapshot — a single shared-lock read of the resolved project/ worktree per wire op, through myco-ops/myco-store-md exactly like the CLI verbs. Nothing here proxies myco serve: the reads are cheap enough in-process, and keeping the driver a pure reader means it can never mutate the ledger.

TUI → view mapping (the retirement checklist — myco-tui’s screens and where each landed):
