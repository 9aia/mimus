data — one read of a repo’s project/ worktree per wire op.

The driver is a reader: every view/query resolves the target project, takes the shared worktree lock for the span of the load (same discipline as myco status), and drops it. No mutations, no index — myco serve stays the write/embedding surface; this crate only needs what the TUI rendered.

Project resolution order (first hit wins):

  1. Request params — dir (a project/ worktree path) or root (a repo root; <root>/project is tried), e.g. pavo view myco:board --param dir=/path/to/repo/project.
  2. $MYCO_DIR — treated as dir.
  3. cwd discovery — myco_ops::discover walks up from the driver’s cwd for a qualifying project/ worktree (the same rules myco verbs use, including myco.toml’s project_dir).

When nothing resolves, Snapshot::error carries the reason and every query degrades to an {"error": …} payload — the wire stays ok:true so hosts render the failure inline.
