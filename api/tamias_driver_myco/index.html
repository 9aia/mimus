tamias-driver-myco — the pavo view driver for a repo’s project/ ledger.

Verbs (the tamias driver contract):

  • manifest — print the [DriverManifest] JSON (discovery probe; never touches project state).
  • capabilities — {"capabilities": ["pavo"], "verbs": […]}.
  • ops — the engine ops manifest: every myco CLI verb as a cli.<verb> wire query, derived from the engine’s own myco::registry::VERBS table.
  • run <argv> — engine passthrough: tamias-driver-myco run board ≡ myco board. Also the child side of cli.* wire queries (ops::run_verb re-execs this same verb so engine output never touches the serve stream).
  • cli <myco argv> — the tamias bins[] shim verb (T-006): tamias bin exec calls it as cli --dir <pkg> --name myco <argv> for the shim: cli bin declared in libraries/myco/tamias.yaml. myco’s engine IS the CLI, so this is a passthrough — strip the two standard driver flags and hand the rest to myco::run_from with inherited stdio. That keeps full argv parity the retired myco binary had: --help/--version, every bounded verb, and the unbounded surfaces (myco serve JSON-RPC, myco ui TUI, myco batch) all stream end-to-end.
  • serve — ndjson JSON-RPC on stdio: {"op":"manifest"}, {"op":"views"}, {"op":"view","view":…,"params":{…}}, {"op":"query","query":…,"params":{…}} → {"ok":true,"result":…} / {"ok":false,"error":…}. query:"ops" answers the ops manifest; query:"cli.<verb>" runs the engine op.

Optional surface: feature mcp embeds pavo-driver-kit’s surface layer — mcp serves the ops manifest as MCP tools on stdio, equivalent to the standalone tamias-driver-mcp minus the PATH/discovery hop. There is no cli feature: cli is the shim verb above, not a generated surface.

Which repo: each view/query resolves its own target — params.dir/params.root → $MYCO_DIR → cwd discovery (see data.rs for the exact order). Engine ops are the exception by design: cli.<verb> re-execs run in the request’s repo and lets myco::dispatch own the outcome — writes keep the engine’s own semantics (per-verb commit, Actor: trailer). manifest/views are project-free so pavo can enumerate drivers anywhere.
