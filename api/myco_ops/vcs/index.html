VCS access for the ledger — every git call routes through the shared [lasius_vcs] port (P-019/P-026) backed by [lasius_vcs_git::GitVcs], the stateless git-CLI impl.

This module keeps the myco-shaped surface the verbs were written against (free functions over a &Path, io::Result errors that render as git <args>: <stderr>) and owns the pieces that are ledger policy rather than generic VCS mechanics: the myco/myco@localhost committer fallback, the commit-per-verb composition (commit_all), and the create-only orphan branch (create_orphan_branch).

LogEntry
Re-exported so front-ends can name log entries without taking a direct lasius-vcs dep. One cheap log-style entry — %H %as %s, newest first. Lighter than [CommitInfo] (no body/paths); for ledger-style consumers that only need hash/date/subject.

attach_branch
Attach the checkout at dir to name, keeping its current HEAD as the branch tip — the repair for a detached ledger worktree (myco check --fix). checkout -B is create-or-reset, so a branch left behind by an earlier run loses to the commits that are actually here; git refuses when another worktree holds the branch, which is precisely the case a human must arbitrate.
branch_exists
refs/heads/<name> exists.
commit_all
git add -A -- . && git commit --allow-empty -m <msg> — the auto-commit-per-verb path writes files first, then this. The stage is scoped to repo (-- .): when repo is a plain subdirectory of a bigger repo rather than a real worktree, changes elsewhere aren’t swept into the ledger commit (the port’s stage_all is a whole-tree add -A — too broad here). A bare commit could still pick up foreign staged changes, so those are refused rather than committed under our message (a commit -- <pathspec> alternative can’t express the first commit — the pathspec must match known files). --allow-empty keeps no-op verbs honest in the audit trail.
commits_ahead
How many commits HEAD has that rev doesn’t — None when rev doesn’t resolve (no such local or remote ref).
commits_behind
How many commits rev has that HEAD doesn’t — the mirror of commits_ahead; None when rev doesn’t resolve.
common_dir
git rev-parse --path-format=absolute --git-common-dir — the shared git dir for all of dir’s worktrees (<main>/.git), resolved from inside any of them.
create_orphan_branch
Create name as an orphan branch via plumbing — mktree an empty tree, commit-tree a root commit, update-ref the branch. Unlike git checkout --orphan this never disturbs the index or working tree of the current checkout.
fetch_branch
git fetch <remote> <branch> — best-effort refresh of one remote-tracking ref (no prune). Err on any failure — callers treat fetch as advisory, never a hard gate.
git
git -C <repo> <args>; true on exit status 0. stdout is silenced — progress chatter (HEAD is now at …, commit summaries) must never pollute a verb’s --json stream; stderr is silenced too (the port’s exec), where the retired myco-git helper let it through for diagnosis.
git_ident
git -C <repo> <args> for commands that need a committer identity (commit, commit-tree). When the repo can’t resolve one — git var GIT_COMMITTER_IDENT makes the same check the commit machinery does — a -c user.name=myco -c user.email=myco@localhost fallback is injected for that one invocation. A configured identity (or GIT_*_NAME/GIT_*_EMAIL env) always wins, since the probe sees it first.
git_out
git -C <repo> <args> → trimmed stdout. stdin is /dev/null — plumbing commands that read stdin (mktree) get an immediate EOF instead of blocking on the caller’s terminal. Errors render git <args>: <stderr>, matching the retired myco-git error.
has_changes
Uncommitted/untracked changes under dir (status --porcelain -- . non-empty). Scoped to dir itself — when dir is a plain subdirectory of a bigger repo rather than a real worktree, changes elsewhere in the containing repo don’t count. Git failures propagate: callers must not mistake “status failed” for “clean”.
has_commit
True when rev resolves to an object (cat-file -e).
head_commit
git rev-parse --verify HEAD — the commit a worktree/repo is on, None when the branch is unborn. Index freshness is stored head == head_commit(worktree).
is_detached
dir is a git checkout whose HEAD is detached — commits made there belong to no branch and become unreachable as soon as the worktree moves. None when dir isn’t a checkout at all (the plain-directory ledger shape), which is not a defect.
log
One git log line, parsed — re-exported LogEntry.
main_worktree
The main (first) worktree of the repo dir belongs to — i.e. the repo root when dir is a linked worktree like project/. Derived from --git-common-dir (<main>/.git → <main>), with a worktree list fallback for old git — the port’s main_worktree already folds the two together.
merge_ff
git merge --ff-only <rev> — fast-forward HEAD to rev. Fails when the histories diverged (that’s rebase’s job).
rebase
git rebase --autostash <rev> — replay local commits onto rev, stashing any dirty tree first. A conflict stops the rebase mid-flight (see rebase_in_progress/unmerged_files) and surfaces as Err.
rebase_abort
git rebase --abort — bail a conflicted rebase, restoring the pre-rebase tip (autostash pops the worktree back too).
rebase_in_progress
A rebase/merge is stopped mid-flight in dir — the state dirs exist (REBASE_HEAD alone persists after a finished rebase, so it can’t be the signal).
repo_root
git rev-parse --show-toplevel — the worktree root containing start (Err outside a repo).
sync
git fetch origin --prune.
tracks_branch
Does origin’s fetch refspec publish branch into refs/remotes/origin/? A repo cloned with --single-branch only tracks some branches, so origin/<branch> can sit stale forever while git push still succeeds — comparing against it would report “unpushed” no matter what the user does.
unmerged_files
Worktree-relative paths with unresolved merge conflicts (status --porcelain XY codes where both sides moved).
worktree_add_branch
Checkout branch into dir — the project/docs worktree path: a real branch, not a detached rev. The branch must already exist (orphan-created or adopted from the remote); the port’s worktree_add_existing, not worktree_add_branch which would create a new branch at the rev.
worktree_branch
The branch a worktree dir has checked out (None when detached or not a worktree).
