Source
Expand description

Config plumbing — ops owns the policy (which file is the repo layer, merged vs repo-only reads) and the TOML wiring: parsing rides scarab-config-toml (P-017 — the per-repo myco-config/myco-config-toml crates are gone), while the two-layer merge stays here because its collision rules are myco’s, not scarab’s generic fold. Only myco_core::Config crosses the seam.

Structs§

ConfigLoader
The two config reads ops needs. layered runs the impl’s layered search — Some(path) pins the repo layer, None its default probe (env → cwd → user layer); file reads exactly one file with no search and no merge — myco check lints the repo layer alone so findings are identical for every user.

TOML
The TOML loader every front-end binds — the scarab-backed replacement for the retired myco-config-toml crate.

Functions§

default_view_for
The layer’s default_view — same path policy as kinds_for: repo myco.toml (or $MYCO_CONFIG) if present, the impl’s default probe (user layer) otherwise. Missing config, not error.
kinds_for
The kind table for the repo rooted at root — the repo-layer myco.toml (or $MYCO_CONFIG), same path policy as discover’s project_dir read. The prelude on absence or error — a broken config already fails the verbs that read it strictly, and check lints [[kinds]] on its own.
sync_auto_fetch_for
sync.auto_fetch for the repo rooted at root — same path policy as kinds_for. Missing/broken config → true (the documented default); the fetch itself is best-effort either way, so a config read failure can’t strand a mutation.
