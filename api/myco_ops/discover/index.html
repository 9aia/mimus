Project discovery — resolve the project/ worktree a verb should act on.

Order: --dir (explicit worktree) → --root (repo root → <root>/project) → cwd inside the worktree itself → myco.toml’s project_dir (only the discovered repo’s own myco.toml, and only a path that stays inside it) → walk up from cwd for a project/ dir that is a git worktree on branch project (or, weaker, any project/ holding a TODO.md). The walk is capped at the worktree root containing cwd — an ancestor’s project/ above it can be a different repo’s ledger (git worktrees live anywhere) and must never win.

Functions§

discover
Resolve the project for verbs that need one. dir/root are the global flags; cfg loads myco.toml (project_dir) via the front-end’s impl; everything else is discovery.
discover_at
discover with an explicit cwd — the workhorse, and what tests and the index universe drive (no process-global set_current_dir races). No index: the org-ledger fallback stays off.
discover_with
discover with the repo index available — the last-resort fallback for the org-ledger pattern: when plain discovery fails inside a registered repo that has no ledger of its own, the org entry’s worktree answers instead. None (or an unreadable index) keeps discovery exactly as strict as before — unregistered repos still fail.
qualifies
d is usable as the project dir — a git worktree rooted at d checked out on project, or at minimum a dir holding TODO.md.
repo_root_for
Resolve the repo root for myco init / migrate — the verbs that create the worktree rather than requiring it. --root wins; then --dir — the ledger belongs to the repo whose work tree contains the target, and a linked-worktree container resolves to the repo’s main worktree so .gitignore/ AGENTS.md land on the main checkout, not a worktree’s feature branch; then the git repo containing cwd.
worktree_path
The worktree path init/migrate should use — --dir (canonicalized) or the conventional <root>/project.
