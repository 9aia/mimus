Item ops — the I/O shell around myco-core’s domain: store open/save, the commit-per-mutation tail, item-file reads, and the shared output verbs. The pure pieces (ledger doc surgery, state walks, compact, tree_view, require_kind, NewItemMeta) live in myco-core and are re-exported here so call sites read items::X either way.

LockedStore
A store handle holding the worktree lock — exclusive from open_with (mutating verbs), shared from open_read_with. The lock releases when this drops. Derefs to the inner store, so &locked coerces to &S at every call site. Generic over the store — the front-end (composition root) names the impl.

archive_done
Archive a done task subtree into DONE.md — load, push, save. Callers that must validate before any write stage the doc themselves (load_done → done_push → save_ledger → save_done) — this convenience form loads fresh, so a dup id surfaces only after earlier writes landed.
commit
The standard mutation tail — one atomic commit on the worktree. actor is the verb’s actor (--actor/--owner where the verb takes one) — stamped as the Actor: trailer; None → cli.
compact
T-001 open pri:high owner:devin #core title — the compact human list line. Thin wrapper over Item::compact.
done_push
Append item (subtree included — every node must already be terminal, Done or Cancelled; emit rejects anything else) to the done doc’s flat unsectioned list. Duplicate ids — the item’s whole subtree — are refused: an id lives in exactly one place.
find_item
Locate an item anywhere in the ledger — TODO.md, BACKLOG.md, or an item file (live or archive/). Returns the item, its location label, and the body for file-backed items.
item_for_edit
Load a file-backed item for mutation. Archived items are refused — save_item writes to the live dir, so editing one would silently un-archive it.
item_rel_path
<dir>/<filename> for a file-backed item — the store impl’s own naming grammar ([Store::item_path], archive scope included), falling back to the bare id for kinds with no file form.
list_files
The shared <kind> list — live item files, plus archive/ entries when include_archived.
load_done
DONE.md — the done-task archive (todo done lands here).
load_ledger
Load both ledger docs through the store.
marked_json
(item, archived) pairs → a bare array of item objects, each tagged "archived": bool — the --json list shape. Live and archived items share one array; the flag is the marker.
new_file
The shared <kind> new body — alloc id → apply meta → body or template → save_item → commit + report.
open_read_with
open_with under the shared read lock — read-only verbs (status, view, list, resume, …). Readers don’t block each other; a reader meeting a live writer fails fast.
open_read_with_index
open_read_with with the repo index — see open_with_index.
open_with
Resolve the project + open the store mk builds under the exclusive mutation lock — every verb that writes the ledger takes this path. mk gets the discovered worktree and names the concrete impl (myco’s ops::store_at → MdStore), so this crate stays generic over [Store]; cfg is the same story for config (discovery reads project_dir). The lock spans discovery → mutation → the per-verb autocommit; contention fails fast (another myco process is writing — retry) instead of corrupting the ledger.
open_with_index
open_with with the repo index at discovery’s disposal — the org-ledger fallback: a registered repo with no ledger of its own resolves to the ledger = "org" entry’s worktree. None keeps discovery strict (unregistered repos fail).
print_list
--json → a bare array of item objects; else compact lines.
print_tree
Like print_list for depth-tagged items — human output indents children 2 spaces per level under their parent.
query_files
The read behind list_files — live item files (plus archive/ entries when include_archived), filtered, as (item, archived) pairs. Non-CLI front-ends (myco serve) shape it themselves — marked_json is the list shape.
report
Standard mutation output: --json gets payload plus a committed key; human output is one line.
require_kind

The shortest legal path from → to, or the transition error naming the valid targets.
targets
"claimed, in-progress, deferred" / "none (terminal)" — the valid-targets suffix on transition errors.
today
Today’s date — created: values and comment timestamps.
tree_view
Depth-tagged pre-order view — list UIs indent children under their parent by it. Iterative (explicit stack, children pushed reversed to pop in file order): trees can nest past any sane recursion depth.
walk_descendants_to
Walk every descendant to to — subtree moves keep the ledger consistent: a deferred parent’s children can’t stay open in BACKLOG.md, and children park/unpark with their parent. Nodes already at to are left alone (identity isn’t a transition). All-or-nothing: the whole subtree is validated before any status moves, so an unreachable target can’t leave earlier siblings half-transitioned.
walk_to
Walk item along status_path to to, validating each hop.
