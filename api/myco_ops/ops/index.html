Source
Expand description

Shared plumbing for the lifecycle verbs — the project/ scaffold and the auto-commit-per-verb machinery.

Every mutating verb ends in one atomic commit on the project branch (--no-commit or $MYCO_NO_COMMIT opts out, e.g. for tests and dry runs). Commits happen only when the worktree actually changed — a no-op verb leaves no noise in the audit trail.

autocommit
One atomic commit of everything under dir — the auto-commit-per-verb path. msg gains the Actor: trailer (commit_msg; actor is the verb’s actor, None → resolve_actor over dir — $MYCO_ACTOR → human:<git user.name> → cli). No commit when disabled or when the tree is clean. Returns whether a commit was made.
commit_msg
msg + the Actor: trailer — every myco commit names the verb’s actor in the message body (T-011: actor-tagged trailers, not per-actor git authors — author/committer stay the repo’s stable user.name/user.email identity, or the myco@localhost fallback). None resolves to DEFAULT_ACTOR. The subject line is untouched, so %s parses (e.g. report’s velocity walk) never see it.
commit_paths
Commit only paths inside dir — used for repo-root edits (.gitignore, pm/ removal) so an unrelated dirty tree isn’t swept into the verb’s commit. Returns whether a commit was made.
commits_enabled
Are verb commits enabled? --no-commit or $MYCO_NO_COMMIT (any value) suppresses them.
ensure_committable
Mutating verbs must not write a ledger they cannot commit. A detached project/ worktree is the failure mode that costs the most: every write lands, no branch records it, and the audit trail is gone the moment the worktree moves. check reports and repairs it; every write path refuses it first.
ensure_synced
Refuse a mutation while the ledger branch is behind its tracked remote — every verb commit would deepen the divergence myco sync exists to close.
history_list
The redoable stack, next-redo first — backs myco undo --list.
index_template
Default index.md — a human map of the ledger.
lock_shared
The shared read lock — concurrent readers don’t block each other, but a reader contending with a writer fails fast rather than rendering a mid-verb ledger.
lock_worktree
The exclusive mutation lock — every load→mutate→save→commit verb holds it for the verb’s whole life (including the autocommit). Fail-fast on contention: concurrent writers corrupt the ledger (dup ids, last-writer-wins), so the second one gets a retry hint instead.
print_json
Pretty JSON to stdout.
print_paged
Print text, paging it through the user’s pager when stdout is a tty — less -F exits instantly for one-screen output, so callers can page unconditionally. Non-tty output, a disabled or unspawnable pager all fall back to println!.
redo_depth
How many commits redo could still restore — 0 when the journal is empty or its top anchor no longer matches HEAD.
redo_last
myco redo — restore the commit the last undo moved away from: pop the top of the undo journal (<git-common-dir>/myco-history.json, see crate::history) and git reset --hard to its target. Repeatable — each pop exposes the next-older undone commit, which is the redo stack single-step reflog tricks can’t express.

scaffold
Create every missing scaffold piece in the worktree; existing files are never overwritten. root is the store’s worktree dir (the .gitkeep sweep is raw fs — the port has no “list dir” verb). Returns the rel paths created.
undo_last
myco undo — move the worktree’s branch tip back one commit (git reset --hard HEAD~1). Every mutating verb is exactly one commit on the ledger branch, so the reset is the inverse mutation — including file deletions (todo done’s removed line comes back whole). The commit stays reachable through the reflog; nothing is garbage-collected.
