myco-ops — the I/O shell every front-end calls.

myco-core is pure domain (ledger doc surgery, state-machine walks, item metadata); this crate is everything that touches the outside world: discover resolves the project/ worktree via git, config owns the myco.toml loader (TOML — scarab parsing + myco’s two-layer merge policy), universe resolves the index universe (lasius clones ∪ repos.toml), ops owns the scaffold + commit-per-mutation machinery, vcs routes every git call through the shared lasius-vcs port, and items is store open/save + the verbs’ shared mutation/output tail — re-exporting the core symbols so call sites read items::X for either. myco (CLI) is a thin clap shell over this; myco-driver (the pavo view driver) reads through the same functions, so every front-end sees identical state.

Modules§

config
Config plumbing — ops owns the policy (which file is the repo layer, merged vs repo-only reads) and the TOML wiring: parsing rides scarab-config-toml (P-017 — the per-repo myco-config/myco-config-toml crates are gone), while the two-layer merge stays here because its collision rules are myco’s, not scarab’s generic fold. Only myco_core::Config crosses the seam.
discover
Project discovery — resolve the project/ worktree a verb should act on.
history
Undo journal — myco-history.json in the repo’s git common dir (<main>/.git, shared by every worktree). It records only the future: commits undo moved away from that redo can still restore. The ledger’s linear commit chain stays the “past” — the journal is disposable derived state, never committed to project/.
items
Item ops — the I/O shell around myco-core’s domain: store open/save, the commit-per-mutation tail, item-file reads, and the shared output verbs. The pure pieces (ledger doc surgery, state walks, compact, tree_view, require_kind, NewItemMeta) live in myco-core and are re-exported here so call sites read items::X either way.
links
links — the invalidation driver for the link index (P-005).
ops
Shared plumbing for the lifecycle verbs — the project/ scaffold and the auto-commit-per-verb machinery.
universe
The index universe — which repos index-sourced views cover (P-026).
vcs
VCS access for the ledger — every git call routes through the shared [lasius_vcs] port (P-019/P-026) backed by [lasius_vcs_git::GitVcs], the stateless git-CLI impl.
verb
Config-declared verbs — [verbs] from merged config layers (P-007). Resolution mirrors view.rs: config files are I/O so the merge lives here; the verbs themselves are executed by the front-end (cli). The builtin surface is injected — ops doesn’t know the registry, callers hand it in like ConfigLoader.
view
Named views — built-in presets plus [views] from merged config layers (P-006). Resolution is I/O (config files), so it lives here; evaluation is pure and stays in myco_core::view.
