ops — the tamias content-type verbs of tamias-driver-bupha.

tamias discovers tamias-driver-<type> executables and runs <verb> --dir <payload> --name <pkg> [--config <f>] for the lifecycle three (install/deploy/uninstall) and any provider verb the driver’s capabilities advertises (host, hooks, health, status, logs, config-schema). This module is that surface — the pavo verbs (manifest/serve/capabilities) stay in main.rs/lib.rs; main.rs dispatches on the subcommand, and tamias verbs always carry --dir/--name while pavo verbs never do, so the two surfaces can’t collide.

Config model: the bundle payload ships fleet.toml — a complete bupha_core::Config doc (every [[repo]], [runner], [status], [queue], …) except the two fields the manifest owns: tunnel.public_url and trigger.listen, which deploy injects from provider.ingress[] (the same values hooks register points GitHub at — one source of truth, no drift). deploy writes the merged doc to ~/.config/bupha/bundles/<name>.toml; the provider units’ tamias-driver-bupha host|worker --config <that path> consume it (host runs the watcher engine in-process via bupha-watch, worker polls ci-job entities on the [worker] node — both through the same merged config; ADR-0006: units exec the driver binary, not a cargo-installed bupha). The host/hooks/provider.ingress[] path is standalone/dev mode (ADR-0007): production webhook/forge ingress is a peregrin campaign listener that normalizes deliveries through bupha’s Trigger semantics and enqueues ci-job via ci.enqueue, consumed by the worker service — use the listener verbs only where no peregrin runs. Per-bundle files beat merging into bupha.yaml: the config loader (bupha-config-file) has no include mechanism and a merge-writer would have to track provenance to stay idempotent — a dedicated file is trivially regenerable and uninstall is a delete.

Secrets are env-var NAMES only (secret_env, token_env) — values resolve env → cuora → OS keyring → ~/.config/bupha/env (cuora canonical per T-056), the same chain bupha itself uses, and are never printed or written.

Functions§

config_schema
config-schema — the JSON Schema (draft 2020-12) of the operator config deploy writes: a bupha_core::Config doc (the fleet TOML/YAML — YAML is a JSON superset for these shapes) with tunnel.public_url/trigger.listen manifest-owned. Deliberately permissive like the sibling drivers’: operators may hand-edit keys the generator doesn’t emit, so only the sections a working watcher needs are required.
deploy
deploy — write the operator config tamias-driver-bupha host|worker --config consumes: fleet.toml with tunnel.public_url and trigger.listen/kind filled from provider.ingress[] (the manifest wins those fields — they’re the same values the forge hooks point at). Regeneration is idempotent: the file is wholly rewritten from payload + manifest every time.
health
health — probe each ingress listen+path with the webhook ping (POST <listen><path> + X-GitHub-Event: ping → 200 pong), falling back to systemctl --user is-active per provider unit when no ingress declares both. Prints a JSON status object.
hooks
hooks register|uninstall — upsert/remove the GitHub webhooks the manifest’s provider.ingress[].hooks[] declare, via bupha_github’s REST path (exact-URL match, idempotent).
host
host — engine-host mode: run the watcher pipeline in-process so deployed provider units exec this driver binary instead of a cargo-installed bupha (ADR-0006: no user-facing bupha CLI on the host path; bupha T-052).
install
install — no-op. Like the peregrin driver, the operator config is deploy’s job: install only sees the evictable fetch-cache payload dir; the stable ~/.config/bupha/ write belongs to deploy, which tamias deploy runs against the store entry.
logs
logs — journalctl --user -u <unit> over every provider unit, newest lines entries, no follow (dispatch is bounded — a -f would just be killed). Returns the journal text.
parse_flags
Parse --flag value / --flag=value argv. Unknown flags are an error — a typo’d flag must not silently no-op a lifecycle verb.
run
Run one tamias verb. verb is the subcommand main.rs already matched; args is the remaining argv (--dir … --name … plus verb flags). Prints the verb’s report to stdout; errors go to stderr with a non-zero exit — the tamias dispatch contract.
status
status — per-unit systemctl --user is-active/is-enabled as a JSON object; units systemd can’t answer report "unknown".
uninstall
uninstall — remove the config deploy wrote. --dir is accepted for dispatch parity and ignored; --config/--name resolve the same path deploy used.
worker
worker — the ci-job consumption loop (P-002 §4.1): poll kind="ci-job" entities on a hypha/peregrin node, ci.claim the pending ones this box’s [worker] labels cover, run them through the same bupha-watch pipeline host uses (worktree → runner → status sink), ci.renew on the run ticker, ci.complete with the result. This is the second service a fleet deployment runs alongside host — the watcher ingests pushes (standalone mode) while workers execute jobs the entity plane hands out; in peregrin-hosted mode the plane lives on the node and host isn’t needed at all.
